# 文字视图结构扩展设计

## 目标

在保持“纯文本重排阅读”定位的前提下，为原文图片和表格保留可跳转占位，并让视觉模型显式识别页眉后丢弃，减少页眉误判为正文标题的问题。

## 范围

- 扩展逐页视觉模型允许输出的 item 类型。
- Python 规范化层过滤页眉、保留图片和表格占位。
- 完整网页阅读器渲染图片、表格占位并提供 PDF 跳转。
- 保持现有 PDF 页锚定、脚注和跨页启发式不变。

不实现：

- 全书重复页眉检测。
- 基于 OCR bbox 的页眉判断。
- 图片、表格内容转录。
- 跨页段落 AI 合并。
- 图片标题、表格标题、坐标或其他附加字段。

## AI 输出契约

视觉模型允许输出以下类型：

```text
heading
body
footnote
figure
table
header
```

其中 `header` 是转换过程内部类型，不进入最终电子书 JSON。

图片和表格必须只输出类型：

```json
{"type": "figure"}
{"type": "table"}
```

不得包含 `text`、标题、坐标、编号或其他键。它们在 `items` 数组中的位置表示其在原页阅读顺序中的位置，PDF 页码继承外层页面的 `pdf_page`。

提示词增加以下规则：

- 页面顶部重复出现的书名、章名、作者名属于 `header`，不是 `heading`。
- 页眉即使加粗或字号较大，也必须识别为 `header`。
- 页脚和页码继续忽略。
- 照片、插图、图表、地图等输出 `figure`。
- 表格输出 `table`。
- 不描述图片内容，不把表格内容转录为正文。
- `figure/table` 放在对应阅读位置；脚注仍统一放在 items 末尾。

## Python 规范化

- `heading/body/footnote` 沿用现有字段清洗。
- `figure/table` 忽略模型返回的所有额外字段，规范化为仅含 `type` 的对象。
- `header` 无条件丢弃。
- 未知类型继续丢弃。
- `figure/table` 保持原顺序；只有 `footnote` 移动到 items 末尾。
- 模型失败仍沿用当前空白页降级行为。

## 前端渲染

文字视图按 item 顺序渲染：

```text
figure → “此处原文有图片 · 点击查看 PDF”
table  → “此处原文有表格 · 点击查看 PDF”
```

占位元素保存父页面的 `pdf_page`，但不改变 `.s2e` item 字段。

点击行为：

- 当前为纯文字视图：先切换为双栏视图，再让 PDF 栏跳转到对应页。
- 当前为双栏视图：直接让 PDF 栏跳转到对应页。
- PDF 尚未加载完成：等待当前书的 `pdfPromise` 后跳转。
- 文字栏当前位置保持不变。
- PDF 单栏模式下不会显示文字占位，不增加额外行为。

占位块必须支持键盘操作，使用 `button` 元素和明确的 `aria-label`。

## 兼容性

- 旧 `.s2e` 不含 `figure/table`，继续正常渲染。
- 新 `.s2e` 在旧阅读器中会忽略未知 item，但其他正文仍可阅读。
- 不修改 `.s2e` 包结构和 PDF 页码语义。
- 不修改现有跨页 `_continued` 启发式。

## 验证要求

- Python 测试覆盖 `header` 丢弃、`figure/table` 最小化字段和顺序保持。
- 前端测试覆盖两个占位类型及其父页码。
- 前端测试覆盖纯文字视图切双栏后跳 PDF，以及双栏直接跳 PDF。
- 现有插件生命周期、阅读环境、布局、样书冒烟和生产构建继续通过。
