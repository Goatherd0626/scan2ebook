# 独立网页与阅读器改版

目标：让普通读者在本机浏览器中完成 PDF 转换、导入、阅读，无需 DSH。用户已选择本机服务，并将 Tauri 桌面构建留到后续。

按用户在侧会话确认的选型，采用 React + TypeScript + Vite、Tailwind CSS 与 shadcn/ui 组件方式，复用 Node 本地服务和 Python 转换器。React 负责应用外壳、书库和转换页；原有 JavaScript 阅读引擎通过明确的 DOM 宿主与 readerBridge 接入，保留批注、书签、原页定位和阅读进度。Rare UI 作为交互和组件层次参考，本轮未复制其组件源码。视觉采用浅纸色、墨色、淡紫色操作强调和书脊图形；阅读正文保留衬线排版。

网页包含书库与转换两个入口。转换支持拖放/选择 PDF、页数检查、页码范围、临时 API Key、折叠高级设置、实时进度、取消、失败重试、下载产物和导入阅读。任务状态只在进程内保留；刷新可恢复当前任务，API Key 不持久化、不回传、不记日志。

窄屏使用抽屉导航，将阅读工具收进可展开菜单；新书在手机宽度默认使用文字视图。开始转换后优先展示进度，完成后明确提供继续阅读与转换另一本的入口。模型异常或无效结构必须使转换非零退出，不能以空白页代替错误。

Node 服务接收用户选择的 PDF，在应用转换目录中调用已有 Python CLI，并转发其 S2E_EVENT 进度。仅开放回环地址与同源写入，不接受客户端任意文件路径或执行命令。结果经受控下载地址访问。现有 DSH 和书库数据结构继续兼容。

验证使用临时书库、自制样书和替代转换进程，覆盖上传、参数校验、取消、失败、重试、下载与阅读；不运行真实转换或调用付费 API。ego-browser 检查桌面、手机模拟视口、键盘操作与截图。

考虑过纯静态网页，但现有 macOS OCR 不能直接在浏览器运行，故不采用。Tauri 2 可复用前端；后续需要把本地 API 适配为 Rust 命令或受控 sidecar，并单独验证 Python/OCR 打包、签名与公证。本轮不安装 Rust、不构建桌面安装包。
