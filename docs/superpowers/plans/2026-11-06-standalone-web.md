# 独立网页改版实施计划

**目标：** 完成本机网页转换与阅读闭环，改善书库与移动视口交互。

**架构：** React + TypeScript + Vite、Tailwind CSS 与 shadcn/ui 负责外壳、书库与转换界面；通过 readerBridge 接入现有阅读引擎。复用 Node 服务，转换管理器调用 Python CLI，通过受控 HTTP API 获取状态和结果。

**设计：** `docs/superpowers/specs/2026-11-06-standalone-web-design.md`

## 任务

- [x] 转换服务：先增加针对性测试，覆盖 PDF 上传/检查、页码校验、临时凭据、进度、取消、下载、失败与同源限制；实现 `reader/lib/conversion.js` 并接入 `server.js`。
- [x] 独立转换界面：实现 `reader/src/core/conversion.js`；清晰的文件/范围/高级参数/进度/结果流程；接入书库导入。
- [x] 视觉与书库交互：在现有结构上新增统一视觉层；明确导航、文件搜索、直接阅读入口和空状态；适配窄屏与键盘。
- [x] 验证：运行 reader 相关测试和构建；使用临时书库与模拟转换后端，通过 ego-browser 操作上传、转换、取消、重试、下载、导入、搜索和阅读，并按截图修正。
- [x] 文档：更新独立网页使用说明，记录 Tauri 2 接入边界和已验证范围。

## 全局约束

不读取任何真实 API Key，不创建 .env，不运行真实转换、不调用付费模型；不改动已有书库；不发布远端；复用既有依赖，不安装 Rust。

## 重点检查

转换失败后保留文件便于重试；刷新后恢复进行中的任务；取消后不误报完成；页码越界不会启动进程；任务响应和日志不暴露 Key；手机视口可选择文件和阅读，按钮无重叠。
