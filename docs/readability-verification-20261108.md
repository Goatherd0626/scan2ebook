# 字号与重命名验收 · 2026-11-08

本轮继续维护 Web 与 macOS App 的共享前端，不增加依赖。

## 最终调整

| 位置 | 调整 |
| --- | --- |
| 主导航 | 12px → 16px，选中项字重 550 → 700；深色模式使用浅色品牌底和深色字。 |
| 侧栏书籍 | 书名 11px → 14px，选中项加粗；作者与页数 9px → 12px，移到下一行以留出完整书名宽度。 |
| 文件夹 | 侧栏 15px、桌面书库名称 15px，手机名称 14px；桌面卡片最小宽度 190px，图形和整体高度保持紧凑。 |
| 常用界面 | 书库书名 15px，控件与设置常用文字 14–15px，辅助信息 12–14px；Toast 与输入框相应增大。 |
| 重命名 | 文件夹三点菜单直接改名；侧栏提供铅笔、双击和 F2。统一就地编辑框，打开即选中原名称，Enter 保存，Esc / 取消 / 点击外部放弃。书名也可直接从菜单修改。 |
| 详情 | 仅明确选择「查看详情」时打开。普通选择、返回首页、名称刷新均保持已关闭状态，不再挤占书库或遮挡手机上的按钮。 |

修复文件夹展开收起误操作同级第一个文件夹、Esc 误保存、输入期间事件冒泡、重复点击改名入口丢失草稿，以及已打开电子书切换视图时写回旧名称的问题。名称保存后同步侧栏、书库、标签及已打开的详情；其他文件夹在当前页面会话中的收起状态保留。

## 验证

- TypeScript 检查、160 项前端测试和 npm 发布包内容检查通过。新增回归覆盖折叠目标、直接改名、Esc 取消、输入法事件、异步保存唯一提交、失败后保留输入重试、重复点击入口，以及改名后的阅读偏好保存。
- 先复现旧行为，再运行针对性回归；独立只读代码复核后的两项修复已重新通过测试。详情显示状态另经复核，显式打开、字段编辑、保存和取消均可用。
- ego-browser 使用单一 TaskSpace 2，在隔离目录 `/tmp/scan2ebook-rename-qa` 中实测两级文件夹、直接菜单改名、侧栏双击 / 铅笔 / F2、Enter 保存、Esc 取消、同源反复点击保留草稿、保存后刷新、书名修改后切换阅读视图并刷新，以及显式详情内改名和关闭后返回书库。
- 浏览器实测导航为 16px / 700，侧栏文件夹为 15px、选中书名为 14px / 700。当前机器单次双击检查中，从 dblclick 事件到编辑框插入约 4.7ms；这是本机样书检查，不是跨设备性能基准。
- 390×844 模拟手机视口中改名输入为 16px，保存 / 取消按钮均高 44px；书库和设置文档宽度均为 390px。820×620 模拟小窗口的文档与主工作区宽度均为 820px，无横向溢出。深浅色截图均等待有限动画结束后检查。
- macOS App 约 6.26 MiB，DMG 约 2.40 MiB，沿用轻量 Rust / Swift 引擎和系统 WebKit。构建时离线 OCR 自检通过；最终 App 和安装副本通过签名检查，7 个共享前端文件与浏览器版本逐文件一致。

本轮只使用自制样书与测试文件夹，没有真实转换、模型调用、密钥输入或访问原有用户书库。浏览器与模拟视口检查不替代原生 WKWebView、真实中文输入法、手机键盘或系统对话框验收；没有使用原生窗口自动化工具。应用继续使用本机临时签名，未做 Apple 公证。
